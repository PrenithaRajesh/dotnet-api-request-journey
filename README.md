# Bank API — From `dotnet run` to SQL

A tiny ASP.NET Core Bank API built to understand what actually happens when a request travels through the framework from Kestrel and middleware to Dependency Injection, EF Core, and PostgreSQL.

> This isn't a production-ready project. It's a playground with all the experiments from the article in one place. Clone it, tweak it, break it, and use it to understand how ASP.NET Core works under the hood.

## What's inside

- ASP.NET Core Web API
- Controller-based routing
- Custom middleware experiments
- Dependency Injection (Transient, Scoped, Singleton)
- EF Core + Npgsql
- PostgreSQL with Docker
- EF Core migrations

## Run it locally

### 1. Clone the repository

```bash
git clone https://github.com/PrenithaRajesh/dotnet-api-request-journey.git
cd bank-api-request-journey/Bank.Api
```

### 2. Start PostgreSQL

```bash
docker compose up -d
```

### 3. Restore dependencies

```bash
dotnet restore
```

### 4. Run the API

```bash
dotnet run
```

Open Swagger and start experimenting.

## Try these experiments

- Add constructor logs and see when controllers are created.
- Change `Transient` to `Scoped` and compare object lifetimes.
- Remove `await next()` from middleware and watch the pipeline stop.
- Add a property to `Account` and generate another migration.
- Watch the SQL generated by EF Core when `ToList()` executes.
